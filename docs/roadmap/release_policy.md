# Release Policy

HumaWare should move toward a regular release train once the MVP is running.

## Versioning

Use semantic versioning for stable core packages.

## Release Notes

Every release should include:

- package changes
- public API changes
- message changes
- migration notes
- known safety limitations
- verified robot matrix
- benchmark results where available

## Verification

Do not describe a release as real-robot verified without logs, environment, robot model, firmware version, and git SHA.
